Zee no longer ships an in-repo web app. Browser-based investing workflows now run through OpenBB Workspace, with Zee exposed as a stateless copilot over HTTP + SSE.

## Getting Started

Start the Zee daemon:

```bash
zee daemon --hostname 127.0.0.1 --port 3210
```

Then configure OpenBB Workspace to use:

- `GET http://127.0.0.1:3210/openbb/agents.json`
- `POST http://127.0.0.1:3210/openbb/query`

:::caution
If `ZEE_SERVER_PASSWORD` is not set, the server will be unsecured. Set it before exposing Zee beyond loopback.
:::

---

## Configuration

### Authentication

OpenBB Workspace should send either:

- `Authorization: Bearer <ZEE_SERVER_PASSWORD>`
- `X-Zee-Token: <ZEE_SERVER_PASSWORD>`

Trusted browser origins default to loopback plus hosted OpenBB Workspace origins.

---

## Workspace Flow

Each `/openbb/query` request is stateless. OpenBB sends the full conversation history plus widget context on every request, and Zee maps that history back onto a matching session.

When Zee needs client-side widget data, it emits `copilotFunctionCall` for `get_widget_data`, OpenBB fetches the data, and then re-posts the conversation with a `tool` message so Zee can continue.

---

## Attaching a Terminal

You can still attach the TUI to the same backend:

```bash
# Start the backend
zee serve --port 4096

# In another terminal, attach the TUI
zee attach http://localhost:4096
```

This keeps the TUI and OpenBB copilot on the same daemon and memory backend.
